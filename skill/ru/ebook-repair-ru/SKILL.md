# calibre-ebook-repair

Пакет читает библиотеку calibre и пишет только в рабочую папку. В библиотеку пишет одна команда, `apply`, и запускает
её пользователь.

## Где пакет

1. `~/calibre-ebook-repair` — туда его клонирует README.
2. Иначе найти папку с `ebook_repair/__main__.py`, например
   `find ~ -maxdepth 5 -path '*/ebook_repair/__main__.py' 2>/dev/null`.
3. Не нашёлся — спросить пользователя, где он. Без спроса ничего не клонировать и не ставить.

Все команды — из этой папки: `cd <пакет> && python3 -m ebook_repair --lang ru <команда>`.
Библиотека: `--library ПУТЬ`, иначе `$CALIBRE_LIBRARY`, иначе `~/Calibre Library`. Нет ни одной — спросить.
Рабочая папка: `--workdir ПУТЬ`, по умолчанию `./ebook-repair-work`. Всю сессию одна и та же.

## Порядок любой починки

1. **Вид ошибки.** `python3 -m ebook_repair --lang ru check [ID ...] [--tag ИМЯ]`. Прочитать итоги и
   `<workdir>/check.tsv`. «Латинский» шрифт, latin-1 и `#genre` `check` не видит: если пользователь описывает их,
   перейти к шагу 3 и смотреть счётчики `repair`.
2. **Образцы.** `python3 -m ebook_repair --lang ru samples KIND ID [COUNT]`, KIND — одно из `heading`, `bold`,
   `replacement`, `mojibake`, `markup`, `empty`. Показать пользователю 1–3 образца сырой разметки и одной строкой
   сказать, что сломано. Число из отчёта — не доказательство, пока его не подтвердила разметка.
3. **Починка в рабочую папку.** Для русских книг с «латинским» шрифтом или latin-1 сначала
   `python3 -m ebook_repair --lang ru build-dict`: без словарей эта расшифровка выключена. Затем
   `python3 -m ebook_repair --lang ru repair ID ...` — по id из шагов 1–2, а не по всей библиотеке.
   В книге с языком ru или en в calibre `repair` удаляет не абзацы, а только сами знаки CJK, и только в блоке, где их
   больше 3. Строка `книга N: пропущена, починить нельзя: …` — книга не обработана, сообщить пользователю.
   Строка `не найдена программа calibre ebook-convert` значит, что AZW3 не сделаны: `apply` такие книги не примет,
   пользователю — поставить calibre и запустить `repair` снова. `ERROR …` в колонке `azw3` после предупреждения
   `Pillow не установлен` — предложить `pip install pillow` и повторный `repair`.
4. **Сверка.** `python3 -m ebook_repair --lang ru verify ID ...`. Книга без расхождений получает
   `<workdir>/<id>/verified.json`, остальные его теряют; `apply` берёт только книги с ним. Каждую строку расхождения
   показать и разобрать. Частые: `нет source.json — почини книгу заново` (папка от прошлой версии — повторный
   `repair`), `EPUB в библиотеке изменился после починки` (повторный `repair`), `id/ссылки изменились` после удалённого
   `<p id>` из одних `�` (такую книгу не применить), `текст разошёлся` в файле, где «латинским» шрифтом набран
   лишь кусок (`verify` разрешает эту расшифровку, только если спецзнаки шрифта есть в 15% слов и больше; книгу не
   применить). Одиночное `AZW3 нет или он старше EPUB` на крошечной книге бывает
   от порога 10000 байт; решает шаг 5.
5. **AZW3.** Для каждой починенной книги
   `python3 -m ebook_repair --lang ru azw3-check "<workdir>/<id>/<файл>.epub"`. Нужно `AZW3 СВЕРЕН` и код 0.
6. **`apply` — пользователю.** Одной строкой: «Закрой calibre и запусти:
   `cd <пакет> && python3 -m ebook_repair --lang ru --library "<библиотека>" --workdir "<workdir>" apply ID ...`».
   В команде — только id, прошедшие шаги 4 и 5, и только после того, как `repair` закончил. Код 2 — calibre открыта.
7. **Проверка после apply.** Прочитать `<workdir>/apply.log` (дописывается при каждом запуске, считается последняя
   строка книги). `verified` и `already-applied` — порядок. `not-verified`, `changed-after-verify` — снова `verify`.
   `other-library`, `library-changed` — книга не тронута, сказать пользователю. `no-file`, `no-backup`, `mismatch` —
   пользователю с id книги. Старые файлы лежат в `<workdir>/<id>/before/<имя>.<md5[:8]>.<расширение>`. `verify` после
   `apply` «для проверки» не запускать: он сообщит `EPUB в библиотеке изменился после починки` и удалит
   `verified.json`, так и должно быть, а повторный `apply` всё равно напишет `уже заменено`. `mismatch azw3` после
   замены EPUB доделывается тем же `apply` ещё раз: он заменит только AZW3.
8. **Заливка, если просили.** Порядок для пользователя:
   1. `python3 -m ebook_repair --lang ru sync` — только подсчёт, показать числа.
   2. `sync --add`, когда пользователь хочет файлы на ридере. В папку, названную как папка библиотеки, он ещё кладёт
      метку `.ebook-repair-library` с именем библиотеки; в любую другую метку не пишет и сообщает `метка не записана`.
   3. Пользователь проверяет ридер.
   4. Снова `sync`: под числами он печатает пути устаревших файлов, по одному в строке. Показать список.
   5. `sync --mirror --yes` — только по прямой просьбе и после «да» пользователя на этот список. Если он остановился
      на «больше половины», показать числа; `--force` — только после второго явного «да».
   `--mirror` отказывает с кодом 2, если папка на устройстве называется не как библиотека, в ней нет метки или метка
   называет другую библиотеку; `--force` эти отказы не снимает. Лечится одним `sync --add` в папку с именем
   библиотеки. `--device-dir` не направлять в общую папку вроде `/sdcard/Books`, а в папке библиотеки не держать
   посторонних файлов: `--mirror` удалит всё, чего нет в библиотеке.

## Нерушимые правила

- `apply` сам не запускать. `sync --mirror` сам не запускать. Пользователю — готовая команда.
- `--yes` и `--force` сам не добавлять никогда. Они попадают в команду только после того, как пользователь увидел
  список удаляемых файлов и сказал «да».
- `apply` — только когда `repair` закончил собирать AZW3 и эти книги прошли `verify`.
- Форматы книг в calibre не удалять, файлы в папке библиотеки не удалять. Лишний формат — страховка пользователя от
  неудачной конвертации.
- Что убрать из библиотеки, решает пользователь. Сообщить, но не делать.
- Кроме `apply`, библиотеку только читать. `metadata.db` и файлы библиотеки руками не править, других команд
  `calibredb`, кроме той, что внутри `apply`, не запускать.

## Коды возврата

| Команда | 0 | 1 | 2 |
|---|---|---|---|
| `check`, `bold`, `build-dict`, `samples` | готово | `samples`: у книги нет EPUB; любая: нет библиотеки | — |
| `repair` | готово, в том числе без `ebook-convert` и с пропущенными книгами | нет библиотеки | — |
| `verify` | расхождений нет | есть расхождения или нет рабочей папки | — |
| `azw3-check` | буквы совпали | буквы разошлись или конвертация упала | — |
| `apply` | у всех `verified` или `already-applied` | любой другой статус | calibre открыта |
| `sync` | готово | ошибка adb, остановка, не совпал размер | нет устройства, их несколько, неверный `--device-dir`, отказ `--mirror` (нет `--yes`, папка названа не как библиотека, нет метки, метка другой библиотеки, пустая библиотека, больше половины устаревших без `--force`) |

## Что repair умеет и чего нет

Чинит: текст в длинных заголовках, файлы жирные от 90%, `<p>` из одних `�`, знаки CJK из мусора PDF (только в книгах ru/en), «латинский» шрифт,
cp1251, прочитанный как latin-1, `#genre`. Только находит: кракозябры (`РћРЅ`), битые картинки и ссылки, пустые главы,
неразбираемый XHTML, разметку, видимую как текст. Починку этого пользователю не обещать: предложить редактор самой
calibre или другой экземпляр книги.

## Язык

Сообщения — по `--lang en|ru`, затем `EBOOK_REPAIR_LANG`, затем локаль. В этом скилле везде `--lang ru`, чтобы строки
выше совпадали с выводом.
